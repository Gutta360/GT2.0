# Sync API contract v1

Base path: `/api/v1`. JSON uses camelCase and ISO-8601 UTC timestamps. Device endpoints require `Authorization: Bearer <deviceToken>`; admin endpoints require `X-GT2-Admin-Token`.

## Provisioning

- `POST /admin/tenants` — `{tenantCode,tenantName}`; returns tenant metadata.
- `POST /admin/tenants/{tenantId}/enrollment-codes` — returns one raw, expiring `GT2E_...` code once.
- `POST /devices/register` — `{enrollmentCode,deviceName,applicationId:"com.gutta.gt2",applicationVersion:"2.0.0",platform:"ANDROID"}`; returns tenant/device IDs and one raw `GT2D_...` bearer token.
- `POST /admin/devices/{deviceId}/revoke` — invalidates future device authentication.

## Incremental events

`POST /sync/events`

```json
{
  "contractVersion": 1,
  "deviceId": "uuid",
  "batchId": "uuid",
  "events": [{
    "eventId": "uuid",
    "contractVersion": 1,
    "entityType": "PATIENT",
    "entityId": "uuid",
    "operation": "CREATE",
    "payload": { "contractVersion": 1, "entityType": "PATIENT", "operation": "CREATE", "patient": {} },
    "entityVersion": 1,
    "createdAt": "2026-10-29T12:00:00Z"
  }]
}
```

The response repeats `batchId`, timestamps and counts, plus one ordered result per event. Status semantics:

- `ACCEPTED`: mutation and processed marker committed; acknowledge locally.
- `ALREADY_PROCESSED`: identical event previously committed; acknowledge locally.
- `REJECTED`: permanent contract, validation, conflict, or ordering failure; preserve locally with message.
- `RETRYABLE_FAILURE`: no mutation committed; preserve and retry safely.

A completed batch ID with identical content replays saved results. Reusing it with changed content returns HTTP 409. The default server maximum is 100 events.

## Snapshots

- `POST /snapshots` — `{sha256,snapshot}` where `snapshot` is the exact JSON document encoded as a JSON string. Returns metadata.
- `GET /snapshots` — lists available snapshots for the authenticated tenant only.
- `GET /snapshots/{snapshotId}` — returns exact JSON bytes and `X-Snapshot-Sha256`/`X-Snapshot-Id` headers.
- `GET /snapshots/{snapshotId}/recovery-package` — returns the selected baseline overlaid with newer accepted tenant patient versions and a checksum for those generated bytes.
- `POST /snapshots/{snapshotId}/recovery-audit` — `{outcome:"SUCCESS|FAILED",details}`.

Errors use `{code,message,timestamp,details}`. Authentication failures are 401, cross-tenant/not-found resources are 404, authorization failures are 403, malformed/invalid contracts are 400, ID reuse is 409, and configured size overflow is 413.
